# Гибрид — личный дневник тренировок

Минимальная PWA для iPhone и GitHub Pages. Чистые HTML, CSS и JavaScript, без сборки, backend, внешних библиотек, шрифтов, аналитики и CDN. Приложение не отправляет результаты тренировок на сервер.

## Что умеет

- Четыре блока: навык / мощность, сила, прикладная работа / work capacity, выносливость.
- 33 упражнения в каталоге, поиск и добавление своих упражнений.
- Тренировка на выбранную дату; любые блоки можно пропустить.
- Для каждого упражнения: вес в кг, количество подходов, повторов, время в минутах и заметка. Дробные значения веса и времени поддерживаются; 90 секунд = 1.5 минуты. Дистанцию, темп и отдых можно записать в заметку. Параметры общие для упражнения; разные веса по подходам можно описать в заметке.
- Автоматический черновик в IndexedDB, в том числе при работе без сети.
- Завершение тренировки с записью истории и очисткой черновика одной транзакцией.
- Последний завершённый результат под названием упражнения. Выбирается по дате тренировки, затем по времени её завершения. Для своего упражнения сохраняй одинаковое название и секцию.
- История с раскрытием результатов, экспорт и импорт JSON.
- Локальные иконки, manifest, service worker, офлайн-кэш и режим отдельного приложения.

## Публикация через GitHub Pages

1. Распакуй `hybrid-training.zip`.
2. Создай на GitHub репозиторий, например `hybrid-training`. Для простого бесплатного варианта выбери **Public**. Сайт и исходники будут общедоступны, но твои локальные тренировки в репозиторий не попадают.
3. Загрузить нужно **содержимое** папки `hybrid-training` в корень репозитория, а не внешнюю папку целиком. `index.html`, `app.js` и `manifest.json` должны быть сразу в корне. Папка `icons` должна остаться папкой с файлами внутри. Можно использовать GitHub → **Add file → Upload files** или Git. Никакие npm-команды не нужны.
4. В репозитории открой **Settings → Pages → Build and deployment**.
5. В **Source** выбери **Deploy from a branch**, ниже ветку **main** и папку **/(root)**, нажми **Save**.
6. Дождись успешного выполнения публикации в **Actions**. В **Settings → Pages** появится адрес вида `https://USERNAME.github.io/hybrid-training/`.
7. Открой именно этот HTTPS-адрес, а не страницу репозитория. Проверь четыре секции и надпись «Офлайн готов».

Все пути относительные: код работает как в корне домена, так и в подпапке репозитория. Переименовывать адреса в коде под свой GitHub не нужно. `.nojekyll` входит в архив; при загрузке через сайт GitHub проверь, что скрытый файл тоже загрузился. У этого проекта нет файлов, требующих обработки Jekyll.

Официальные инструкции:
- https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site
- https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Установка на iPhone

1. Открой опубликованный адрес в **Safari**, в обычном режиме.
2. Нажми **Поделиться → На экран Домой**. Если Safari предлагает «Открывать как веб-приложение», оставь включённым, затем нажми «Добавить».
3. Запусти с иконки при включённом интернете и дождись надписи **«Офлайн готов»**.
4. Создай пробную тренировку, заверши её и проверь «Историю».
5. Включи авиарежим, закрой и снова открой приложение. Проверь, что открываются интерфейс и история, а новая тренировка сохраняется. Это финальная проверка на твоей версии iOS.

Для первого запуска и установки кэша нужен интернет. Поддержка PWA и внешний вид системных меню зависят от версии iOS. Рекомендуется актуальная iOS/Safari. Проверка на физическом iPhone в комплект работ не входила.

## Резервная копия и перенос

**Данные → Скачать JSON** экспортирует всю историю и текущий черновик. На iPhone сохрани скачанный файл в «Файлы» / iCloud Drive. Индикатор экспорта означает подготовку скачивания, а не подтверждение сохранения файла в iCloud.

Для восстановления открой **Данные → Выбрать JSON**. После проверки появится число новых и уже существующих записей. Нажми **Импортировать**:

- новые тренировки добавляются;
- идентичные записи с тем же ID пропускаются;
- различающиеся записи с одинаковым ID отклоняют весь импорт;
- непустой текущий черновик сохраняется; черновик из файла восстанавливается только в пустой;
- некорректный файл отклоняется до записи. Импорт истории и черновика проходит одной транзакцией;
- максимум файла — 10 МБ, до 10 000 тренировок в файле и до 100 упражнений в одной тренировке.

Формат: JSON-объект с `app: "hybrid-training"`, `schemaVersion: 1`, `exportedAt`, массивом `history` и объектом `draft`. У завершённых тренировок есть уникальные `id` и `completedAt`. Параметры упражнений хранятся строками, пустые поля — `""`. Пример формата проще получить экспортом своей пробной тренировки.

История хранится в **IndexedDB конкретного браузера / приложения и адреса сайта**, не в GitHub. Между iPhone и ПК автоматической синхронизации нет. При смене устройства, браузера, адреса или переустановке сначала сделай экспорт. Если история из Safari не появилась в приложении с главного экрана, перенеси её через JSON. Не работай с одним дневником одновременно в нескольких вкладках: черновик общий, последнее сохранение заменяет предыдущее.

Браузер может удалить локальные данные при очистке данных сайта или освобождении места. Регулярно сохраняй резервную копию. JSON содержит твои записи открытым текстом; не загружай его в публичный репозиторий.

Если хранилище недоступно или переполнено, приложение покажет сообщение; текущий черновик останется в памяти открытой страницы, откуда его можно экспортировать. Заполненные числовые поля должны содержать неотрицательные числа; подходы и повторы — целые.

## Локальный запуск для проверки

Не открывай `index.html` двойным нажатием как `file://`: service worker требует HTTPS или localhost. При установленном Python 3:

```sh
cd hybrid-training
python3 -m http.server 8080 --bind 127.0.0.1
```

Открой `http://127.0.0.1:8080/` на том же компьютере. Это только сервер статических файлов для локальной проверки, приложение не требует backend. Для iPhone используй HTTPS-адрес GitHub Pages: обычный HTTP по локальному IP не даёт полноценную PWA.

## Изменение каталога и обновления

- `data.js` — секции и каталог. Сохраняй существующие ID упражнений, чтобы продолжали находиться последние результаты.
- `styles.css` — оформление; `index.html` — оболочка; `app.js` — интерфейс и JSON; `db.js` — IndexedDB.
- `manifest.json` и `icons/` — название и иконки установленного приложения.
- `service-worker.js` — кэш. **При любом изменении файлов приложения увеличивай `VERSION`**, например с `v1.0.1` до `v1.0.2`. Если добавляешь файл, добавь его и в `SHELL`.

Загрузи изменения в ту же ветку GitHub. При следующем запуске с сетью браузер обнаружит обновление. Приложение покажет кнопку «Обновить»: сначала сохраняется черновик, затем включается новая версия и перезагружается страница. Пока кнопку не нажали, продолжает работать старая целостная версия. Обновление кода не очищает IndexedDB. Перед существенными обновлениями сохраняй JSON.

Имена базы данных и кэшей включают путь сайта, чтобы другие репозитории на том же `USERNAME.github.io` не смешивались с этим дневником.
